# Branding & UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Re-skin CB Online in the approved Combat Box "Operations map" direction. The app becomes always dark, with the wordmark header, a map background, translucent panels and Oswald type. App logic is unchanged.

**Architecture:**
- `ui/theme/Theme.kt` becomes the single source of brand tokens: `CbColors`, Oswald typography, a fixed dark colour scheme, and named `CbText` styles.
- Small building blocks in `ui/brand/` (header, map background, panel modifiers, label) give the screen its frame.
- The existing composables are restyled in place. No ViewModel, data or formatter code changes.

**Tech Stack:** Existing only: Compose BOM 2025.08.01 (Material 3 1.3.2), AGP 9.1.1, Kotlin 2.2.10. New assets: two PNGs and one OFL font. No new libraries.

**Spec:** `docs/superpowers/specs/2026-10-03-branding-design.md`. Read it first; §n below refers to it. The approved mockups are in `.superpowers/brainstorm/7875-1791067314/content/design-states.html` (git-ignored).

**Branch:** `feat/branding` (already created from `main`; the spec is committed).

## Global Constraints

- Colours: exactly the §3 token table. Axis = blue `#3D9ED8`; Allied fill = `#D14F43`; Allied **text** = `#E8695E`.
- Always dark: `CbOnlineTheme` ignores `isSystemInDarkTheme()`. The window background is `#161817` from launch.
- System bars: `enableEdgeToEdge(SystemBarStyle.dark(Color.TRANSPARENT), SystemBarStyle.dark(Color.TRANSPARENT))`, using `android.graphics.Color`.
- Fonts: Oswald, one variable TTF at `res/font/oswald.ttf`, used at weights 400, 500 and 600 through `FontVariation`. Body text uses the system font.

**Copy**
- New strings, exact: `current_mission` = `Current mission`, `next_label` = `Next · %1$s`, `pilots_online` = `Pilots online`, `about_mission_data` = `Mission data: campaign-data.combatbox.net`.

- Brand labels are uppercased in code with `uppercase(Locale.ROOT)`. Resources stay in sentence case.

**Scope**

## Review Focus

These inputs aren't named in the spec but are likely to bite. Each has its test in the owning task.
1. **Sections with zero rows** (`Axis (0)` when nobody's online): the header must be a complete rounded panel, not a top-only cap with nothing under it. Covered by Task 2 `sectionPositions` with `rowCount = 0` → `[Only]`.
2. **Friends section mixing online and offline rows:** it must form one continuous panel, with the last offline row taking the bottom corners. Covered by Task 2 `sectionPositions(3)`, and Task 4 calls it with `online + offline` as the row count.
3. **Large font scale (2×):** the countdown, the big player count and Oswald labels grow and wrap inside their cards rather than clipping. Covered by a Task 4 `LargeFont` preview (`fontScale = 2f`).
4. **Landscape and short screens:** with the banner, update banner and stale strip all showing, the list still gets usable height, and the header doesn't exceed about 90 dp at phone-landscape width. Covered by Task 4 `Landscape` (`widthDp = 800, heightDp = 360`) and `AllStrips` (`heightDp = 640`) previews.
5. **Rows scrolling under a sticky header:** the translucent rows must not show through the header. The header uses the **opaque** `Panel`. Covered by Task 4 (`panelSegment(opaque = true)` for headers) and by the device check in Task 5.

### Task 2: Brand building blocks and screen frame

**Files:**
- Create: `app/src/main/java/io/github/riaanjutte/cbonline/ui/brand/Panel.kt`, `BrandLabel.kt`, `BrandHeader.kt`, `MapBackground.kt`
- Test: `app/src/test/java/io/github/riaanjutte/cbonline/ui/brand/PanelTest.kt`
- Modify: `app/src/main/java/io/github/riaanjutte/cbonline/ui/RosterScreen.kt` (frame only)

**Interfaces:**
- Consumes: `CbColors`, `CbText` (Task 1).
- Produces:
  - `enum class SegmentPosition { Only, First, Middle, Last }`
  - `fun sectionPositions(rowCount: Int): List<SegmentPosition>`: positions for a header followed by `rowCount` rows (size `rowCount + 1`).
  - `fun segmentShape(position: SegmentPosition): Shape`: 8 dp radius on that position's outer corners, 0 elsewhere.
  - `fun Modifier.panel(): Modifier`: card panel. It **clips** to 8 dp corners, so children such as the mission card's red strip are clipped too. Background `PanelTranslucent`, 1 dp `PanelBorder` border.
  - `fun Modifier.panelSegment(position: SegmentPosition, opaque: Boolean = false): Modifier`: `segmentShape` clip and background (`Panel` if `opaque`, else `PanelTranslucent`), with **no border**. This is a deliberate refinement of spec §5's "and border": a border can't run continuously across separate lazy-list items without visible seams, so list panels are borderless and cards keep theirs. Record it as a `Ruling:` when executing.
  - `@Composable fun BrandLabel(text: String, modifier: Modifier = Modifier, color: Color = CbColors.Muted)`
  - `@Composable fun MapBackground(modifier: Modifier = Modifier)`
  - `@Composable fun BrandHeader(versionName: String, onOpenUrl: (String) -> Unit)`: status-bar-padded wordmark (`contentDescription = "Combat Box"`) with the ⋮ button (`more_options`), its dropdown (`about`) and `AboutDialog`.
