# CB Online v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build CB Online v1: a native Android app showing the Combat Box online roster, starred friends, and a GitHub update notice.

**Architecture:** One screen in Jetpack Compose. A `RosterViewModel` combines three inputs: a 60-second foreground polling loop over `OnlinePlayersApi`, a DataStore-backed `FriendsStore`, and a one-shot `UpdateChecker`. It runs them through a pure `RosterBuilder` into a single `RosterUiState`. Dependencies are wired by hand in an `AppContainer`, with no DI framework.

**Tech Stack:** Kotlin 2.2.10 (AGP 9.1.1 built-in), Jetpack Compose (BOM 2025.08.01, Material 3 1.3.2), OkHttp 4.12.0, kotlinx.serialization 1.9.0, DataStore Preferences 1.1.7, Lifecycle 2.9.2. Tests: JUnit 4.13.2, kotlinx-coroutines-test 1.10.2, MockWebServer 4.12.0.

**Spec:** `docs/superpowers/specs/2026-10-03-cb-online-design.md`. Read it before starting; section numbers below (§n) refer to it.

**Branch:** create `feat/v1` from `main` before Task 1. Merge back at the end.

## Review Focus

These are inputs the spec doesn't mention but real players will hit. Each one has a test in the owning task.

1. **Duplicate nicknames in one response** (reconnect ghosts): no crash, both rows shown, and the count includes both. Covered by Task 3 `duplicate nicknames are kept`. Task 7 also uses section-and-index list keys, never bare nicknames.
2. **Captive-portal or proxy pages returning HTTP 200 with HTML:** treated as a failed refresh, not a crash or an empty roster. Covered by Task 2 `html body with 200 throws` and `json object instead of array throws`.
3. **Long or symbol-heavy nicknames** (clan tags like `=JG52=Hans`, `[CB]Ace`, non-ASCII names): sorting is stable, and rows stay on one line, ellipsised, with the star still tappable. Covered by Task 3 `symbol-heavy names sort predictably` and the Task 7 long-nickname preview.
4. **Whitespace and case differences between the API and starred names, and one star matching two online players:** both are matched and both listed. Covered by Task 2 `trims nicknames`, and by Task 3 `friends split into online and offline` and `one starred name matching two players lists both`.
5. **Returning after hours in the background with a failed-refresh strip showing:** an immediate refresh, and success clears `refreshFailed`. Covered by Task 6 `stops polling when unsubscribed and fetches on return` and `failed refresh keeps data until next success`.

- [ ] **Step 4: Implement.**
  - Keep the fetch results in a private `MutableStateFlow<FetchState>` (players, lastUpdated, flags), so data survives unsubscribe and resubscribe.
  - Keep `update` in its own `MutableStateFlow<UpdateInfo?>`.
  - The polling algorithm:

```kotlin
private val manualRefresh = Channel<Unit>(Channel.CONFLATED)

val state: StateFlow<RosterUiState> = channelFlow {
    launch {                                   // runs only while the UI collects
        manualRefresh.tryReceive()             // drop a refresh requested while not visible
        var manual = false
        while (true) {
            fetchOnce(manual)
            manual = withTimeoutOrNull(60_000) { manualRefresh.receive() } != null
        }
    }
    combine(fetchState, friends.friends, updateState, ::toUiState).collect { send(it) }
}.stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), RosterUiState())

fun refresh() { if (!fetchState.value.inFlight) manualRefresh.trySend(Unit) }
```

  - **`fetchOnce(manual)`:**
    - Set `inFlight = true` and `isRefreshing = manual && players != null`. `isLoading` stays true only while there are no players.
    - On success: store players, set `lastUpdated = Instant.now()`, clear `refreshFailed` and `errorMessage`. On the first success only, launch `updates.check(currentVersion)` into `updateState`.
    - On a non-cancellation exception: if players exist, set `refreshFailed = true`; otherwise set `errorMessage`. Clear `inFlight`, `isRefreshing` and `isLoading` either way.
  - **`toUiState`:** calls `RosterBuilder.build(players, friends)` when players are present.
  - **`toggleFriend` / `dismissUpdate`:** `viewModelScope.launch` to the repository or update source. `dismissUpdate` also sets `updateState` to null.

- [ ] **Step 1: Add signing and minify.** This is a decision, so use it as written:

```kotlin
val keystoreProps = rootProject.file("keystore.properties")
val debugSignRelease = providers.gradleProperty("cbonline.debugSignRelease").orNull == "true"

android {
    signingConfigs {
        if (keystoreProps.exists()) create("release") {
            val p = java.util.Properties().apply { keystoreProps.inputStream().use(::load) }
            storeFile = file(p.getProperty("storeFile")); storePassword = p.getProperty("storePassword")
            keyAlias = p.getProperty("keyAlias"); keyPassword = p.getProperty("keyPassword")
        }
    }
    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(getDefaultProguardFile("proguard-android-optimize.txt"), "proguard-rules.pro")
            signingConfig = when {
                keystoreProps.exists() -> signingConfigs.getByName("release")
                debugSignRelease -> signingConfigs.getByName("debug")
                else -> null
            }
        }
    }
}
```
